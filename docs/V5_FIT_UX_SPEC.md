## 3. 의상 상태의 단일 규칙

### 선택 시 동작

| 새 선택 | 제거 | 유지 |
|---|---|---|
| 원피스 | 상의, 치마, 바지 | 머리, 신발, 장식, 가방, 소품 |
| 상의 | 원피스 | 기존 치마 또는 바지 및 나머지 |
| 치마 | 원피스, 바지 | 상의 및 나머지 |
| 바지 | 원피스, 치마 | 상의 및 나머지 |
| 기타 | 같은 카테고리 이전 선택 | 다른 카테고리 |

- 같은 아이템을 다시 누르면 해제하는 현행 동작 유지. 머리는 해제하지 않는다.
- 제거된 옷은 숨겨서 보관하지 않는다. 나중에 원피스를 벗어도 이전 상의가 갑자기 복귀하지 않는다.
- 상의만 고르면 기본 반바지, 하의만 고르면 기본 티셔츠가 보이는 것은 정상이다. 임의의 아이템을 자동 추가하지 않는다.
- undo는 한 번의 선택에 따라 함께 바뀐 옷을 한 번에 되돌린다.
- 마법 코디는 기존 착장 위에 누적하지 않고 새 유효 outfit을 만든다. 배경은 유지하고, 마법 코디 대상이 아닌 모자/가방/소품 등 이전 선택도 비워 결과를 명료하게 한다. 비어 있는 후보군은 안전하게 건너뛴다.

### 저장/복원 경계

작은 순수 함수로 정규화와 선택 적용을 공유한다. 별도 상태 관리 프레임워크는 만들지 않는다.

1. 알려진 카테고리이며 `item.category`가 키와 일치하는 유효 ID만 받는다. 잘못된 타입·배열·null은 빈 선택처럼 처리한다.
2. 머리가 없거나 무효이면 `hair_01`로 복구한다. 신발 해제는 유효한 선택이므로 강제로 복원하지 않는다.
3. 과거 저장값에 원피스와 상하의가 같이 있으면 원피스 우선. 원피스가 없고 치마/바지가 같이 있으면 바지 우선. 과거 선택 순서를 추측하지 않는다.
4. 새 터치는 위 표대로 마지막 선택이 우선한다. 이전 저장 정리 규칙을 새 터치 우선순위로 잘못 사용하지 않는다.
5. 시작, 클릭, 마법 코디, undo/reset, 캐릭터 전환, 저장 및 공통 렌더 경계에서 같은 불변 조건을 보장한다. 불필요하게 여러 번 복제하지 않는다.
6. 기존 사진첩 엔트리는 삭제하거나 일괄 덮어쓰지 않는다. 렌더용 복사본만 정규화한다. 로컬 저장 전체 초기화로 오류를 감추지 않는다.
7. 현재 사진첩에는 코디 재착용 버튼이 없다. 사진첩 새로고침 후 보존만 검증하며 재착용 기능 추가는 범위 밖이다.

합격 조건: `dress && (top || skirt || pants)` 및 `skirt && pants`가 모든 정상 상태에서 거짓이다. UI 체크 표시와 실제 렌더가 일치한다.

## 4. 신체와 파츠를 맞추는 방법

### A. 기준 좌표를 먼저 고정

- 논리 캔버스 `360×480`, 원본 `1086×1448` 유지. 동일 가로세로비만으로 착용 위치가 보장되지 않는다.
- `girl01.png`에서 정수리, 좌우 머리 외곽, 눈선, 턱, 목선, 양 어깨, 허리, 양 발목, 발바닥을 직접 측정하여 한 번 기록한다.
- 몸 이미지와 기준점을 겹친 개발용 비교 그림을 만든다. 측정하지 않은 수치를 코드에 추측해서 넣지 않는다.
- 아이템 표시용 그림은 전체 캔버스 좌표를 유지한다. 썸네일 크롭 좌표를 착용 좌표에 사용하지 않는다.
- 임시 SVG는 이 기준에 맞춰 카테고리별 원형 도형을 수정한다. 아이템마다 임의 CSS translate/scale을 누적하는 방식은 피한다.
- 기존 다른 3명은 예전 SVG 몸 좌표를 사용한다. 현재 두 몸 형상에 필요한 작은 분기만 두고, 공통 함수에서 몸에 맞는 착용 그림을 고른다. 일반적인 리깅 엔진은 만들지 않는다.
- `girl01`용 래스터를 다른 캐릭터에 무조건 씌우지 않는다. 호환 검증되지 않은 경우 해당 몸에 맞는 SVG로 동일 아이템을 표현한다. 캐릭터나 카탈로그를 숨기는 것으로 해결하지 않는다.

### B. 머리

- 피부색 정수리 띠가 보이지 않도록 앞머리/정수리 덮개가 머리 외곽을 덮어야 한다. 눈·얼굴 위에 큰 색 덩어리를 그리는 방식은 금지한다.
- 뒤 머리는 몸 뒤, 앞머리와 정수리는 몸 앞. 기존에 잘 맞는 단일 PNG 머리를 모두 분해할 필요는 없다.
- SVG 몸에 포함된 기본 머리와 선택한 머리가 이중으로 보이지 않게 기본 머리의 표시 조건을 정리한다.
- 모자·머리장식 기준점은 정수리/이마 위쪽이다. 눈과 눈썹을 가리지 않도록 조합으로 확인한다.
- 사람과 토끼/곰의 귀는 의도한 레이어에 남아야 한다. 귀를 포함한 전체 실루엣 잘림도 확인한다.

### C. 옷과 기본 옷

- 목 구멍은 목에, 소매는 어깨/팔 시작점에, 허리선은 몸의 허리에 위치시킨다.
- 우선 `dress_05`와 임시 `top_05`를 교정하고 나머지 12개 원피스·모든 상하의로 같은 기준을 확인한다.
- 기본 티셔츠/반바지는 몸 PNG 일부다. 선택 상태에서 지우는 것만으로 없어지지 않는다.
- 먼저 파츠 형상을 맞춰 기본 옷이 의도하지 않은 위치에서 튀어나오지 않게 한다. 넓은 목/소매 등 기본 옷 구조상 맞출 수 없는 경우에만 단정한 기본복의 해당 부분을 별도 기본 레이어로 분리하는 최소 아트 교정을 한다. 피부를 임의 색으로 칠해 덮거나 얼굴/팔을 자르는 마스크는 쓰지 않는다.
- 그림 내부의 목선과 허리 간 거리가 틀린 경우 단순 평행이동만으로는 둘 다 맞출 수 없다. 국소 재편집 또는 해당 파츠 재제작 대상으로 분류한다.
- 기존 얼굴, 체형, 포즈, 따뜻한 외곽선은 유지한다. 다른 그림체로 캐릭터를 재설계하지 않는다.

### D. 신발과 레이어

- 양 발목 중심, 발 간격, 발바닥 높이를 각각 확인한다. 원본 캔버스 중심 정렬만으로 합격 처리하지 않는다.
- 장화가 바지 끝을 덮는 것은 허용한다. 발가락이 신발 밖으로 나오거나 신발 위에 발이 따로 떠 있으면 불합격이다. 샌들의 의도된 피부 노출은 허용한다.
- 중앙 레이어 표를 유지하며 뒤 머리 → 몸 → 하의 → 상의/원피스 → 신발 → 앞 머리 → 모자/장식 → 소품 순서를 검토한다. 옷끼리의 충돌은 레이어 순서가 아니라 상태 규칙으로 제거한다.
- 에디터·완성·사진첩·인물 미리보기는 같은 자산/호환 해석을 사용한다.

### E. 교정 범위와 그림체

- 등록된 PNG뿐 아니라 임시 SVG도 실제 플레이 자산으로 검사한다. 현재 커스텀 아이템 34개, 전체 카탈로그 104개다.
- 임시 그림의 외곽선 색·굵기·둥근 모서리를 기존 아트에 가깝게 정리한다. 70개 전체의 고품질 재생성은 이번 범위가 아니다.
- 래스터 교정이 필요하면 기존 몸과 실패 파츠를 참조한 GPT 이미지 편집을 사용한다. 투명 배경, 전체 원본 캔버스, 정면 포즈, 고정 기준점, 다른 신체/배경 없음 조건을 준다. 생성만으로 정확한 정합성을 가정하지 않고 합성하여 재확인한다.
- PNG 수정 후 기존 변환 스크립트로 WebP도 갱신한다. 이미지가 캐시에 남아 이전 결과를 보여주지 않는지 확인한다.

## 5. 크기·균형·스크롤 설계

### 화면 크기

- 인형과 옷은 한 SVG 내부에서 동일 배율로 축소·확대한다. 개별 레이어의 화면 크기를 따로 계산하지 않는다.
- 인형의 실제 실루엣이 무대 안에서 머리부터 신발까지 보이도록 너비와 높이 중 더 제한적인 쪽에 맞춘다. 종횡비는 유지한다.
- 일반 세로 화면에서는 조작부를 제외한 무대 높이의 약 80~90%를 활용하는 것을 시각 목표로 삼되, 폭 한계와 토끼 귀/모자 여백이 우선한다.
- 폭 560px 제한 때문에 큰 세로 창에서 무대만 늘어나면 위아래 여백이 커진다. 데스크톱에서는 무대/에디터 높이 상한과 중앙 배치를 검토하여 여백을 줄인다. 폭을 넘겨 인형을 키우지 않는다.
- 가로 화면·짧은 화면·브라우저 확대에서 최소 행 높이가 뷰포트를 초과하면 페이지 세로 스크롤을 허용한다. 완료 버튼이 화면 아래 숨은 채 접근 불가능하면 안 된다.
- 상하뿐 아니라 좌우 safe area를 반영한다. 버튼은 최소 48 CSS px, 주요 조작은 가능하면 56px 이상 유지한다.

### 선택 레일

- 터치 스와이프와 브라우저 기본 가로 스크롤을 유지한다. 별도 드래그 라이브러리를 추가하지 않는다.
- 카테고리 레일 위치와 카테고리별 아이템 레일 위치를 메모리에 보관한다. 재렌더 전 저장, 재렌더 후 복원하고 새 범위 안으로 제한한다.
- 카테고리 변경 이벤트가 기존 레일의 위치를 새 카테고리 키로 저장하지 않도록 전환 순서를 주의한다.
- 이야기 진입 등 프로그램이 카테고리를 바꾸면 선택 탭만 필요한 만큼 노출한다. 클릭할 때마다 전체 레일을 처음이나 가운데로 이동시키지 않는다.
- 아이템 선택 및 500/700ms 효과 종료 후에도 위치가 유지되어야 한다. 효과 종료를 DOM 클래스 제거로 처리할 수 있으면 전체 재렌더를 생략한다.
- 재렌더로 사라지는 키보드 초점은 같은 data 식별자의 버튼으로 `preventScroll`을 사용해 복구한다. 화면 전환 시에는 적절한 제목/첫 조작으로 이동한다.
- 가로로 넘치는 레일에는 그림 화살표 이전/다음 버튼을 제공한다. 모바일에서도 스와이프를 모르는 아이가 사용할 수 있게 한다. 최소 48px 터치 영역과 한국어 aria-label, 시작/끝 상태를 제공한다.
- 일반 세로 휠을 페이지 전체에서 가로로 가로채지 않는다. 데스크톱 마우스는 화살표, 트랙패드는 기본 가로 스크롤로 접근한다.
- 카드 오른쪽 일부가 보이는 것은 다음 내용 힌트로 허용하되, 마지막 카드와 선택 체크 표시가 완전히 노출될 수 있어야 한다.

### 썸네일

- 썸네일은 별도 contain 프레임 안에만 그린다. 그림 영역 overflow를 제한하고 글자 영역과 분리한다.
- 카테고리별 크롭이 커스텀/임시 그림 양쪽을 담는지 확인한다. 실제 파츠를 잘라 숨기는 단순 overflow 수정만으로 끝내지 않는다.
- 옷을 작게 그려도 실루엣 전체와 선택 체크 표시가 보이도록 한다. 현재 한 줄 라벨은 유지 가능하다.
- 소품·가방도 현재 preview viewBox와 실제 도형 위치가 다를 수 있으므로 함께 확인한다.

## 6. Luna 실행 단계와 중간 산출물

1. 저장소 상태/지침 확인 → 새 브랜치 → 실패 화면 재현. 변경 전 저장 데이터는 보존한다.
2. 순수 outfit 규칙과 최소 회귀 검사. 충돌, undo, 마법 코디, 과거 저장을 먼저 해결한다.
3. 기준점 측정 및 공통 SVG 교정, 캐릭터별 호환 처리. 실패 파츠 목록을 만든다.
4. 레일 위치/초점 보존, 화살표, 짧은 화면 세로 접근, 썸네일 개선.
5. 목록에서 확인된 래스터만 교정. `dress_05` 단독 합성과 신발 접점을 우선 확인한다.
6. 전수 연락판 및 핵심 조합 화면, 자동 검사 결과를 남긴다. 기능 검사와 육안 검사를 따로 보고한다.

코드는 기존 파일 중심으로 수정하고 새 검사 파일은 필요한 최소 수로 제한한다. 에셋 다운로드/리깅 엔진/에디터 도구/새 카테고리는 추가하지 않는다.

## 7. 합격 기준

### 상태 검사

- 원피스 → 상의 → 치마 → 바지 → 원피스 순서에서 표대로 교체.
- 같은 옷 재선택, 머리 재선택, 신발 해제, reset, undo 정상.
- 과거 `dress_05 + top_05 + pants_02` 저장, 무효 ID, 잘못된 category/타입을 안전하고 결정적으로 정규화.
- 입력 객체와 기존 사진첩 데이터를 변경하지 않는지 검사.
- 반복 마법 코디 최소 100회에서 충돌 0회. 가능한 한 난수 주입/고정 시드로 재현 가능하게 검사.

### 그림 검사

- 첨부 5장에 대응하는 수정 후 화면을 만든다. 스크린샷으로 확정 못 한 모자 ID는 실제 데이터/UI로 확인한다.
- 모든 104개 아이템을 적절한 기본 코디 위에 하나씩 입힌 연락판을 확인한다. 정상적인 상하의 조합도 별도 확인한다.
- 8개 머리의 정수리/눈, 12개 원피스의 목/어깨/허리, 10개 신발의 발목/바닥을 확대 확인한다.
- 각 SVG 몸 캐릭터에도 카테고리 대표 및 이전에 실패한 조합을 입혀 확인한다. 합격하지 않은 캐릭터를 합격으로 보고하지 않는다.
- 기준점이 맞는 것 외에도 실루엣, 윤곽선 이중 노출, 목/발 틈새, 귀 잘림을 육안 확인한다. 수치 일치만으로 자연스러운 착용이라고 판단하지 않는다.
- 에디터/완성/사진첩의 같은 코디가 일관되어야 한다.

### 조작/레이아웃 검사

- 세로 360×800, 390×844, 412×915; 짧은 390×640; 가로 844×390; 데스크톱 1366×768 및 큰 세로 창 확인.
- 마지막 카테고리와 마지막 아이템까지 스와이프/화살표로 도달.
- 끝으로 스크롤 → 아이템 선택 → 1초 대기 → 음소거/undo/카테고리 왕복 후 위치·초점 확인.
- 200% 브라우저 확대, 리사이즈, 사진첩 20장 상태에서도 필요한 조작에 도달.
- 이미지 로딩 완료 후 화면 증거 저장. 데스크톱 모바일 에뮬레이션과 실제 Galaxy 기기 검증 여부를 구분해 보고한다.

### 기존 검사

- `.github/workflows/validate.yml`의 구문 검사, `check-data.js`, `audit-assets.js`, `scripts/audit-story-mode.js --strict`, `scripts/verify-runtime-assets.py`를 실제 실행한다.
- 새 브랜치는 현재 push 허용 목록에 없다. 자동 검증이 필요하면 해당 브랜치를 목록에 추가하거나 PR 트리거를 이용한다. 실행되지 않은 CI를 통과했다고 보고하지 않는다.
- 이미지 수정 시 WebP 변환 후 검사. 서비스워커 캐시로 수정 전 자산이 보이는 경우 원인을 해결하고 저장 데이터는 보존한다.
- 이야기 추천은 권유로 유지하고 선택을 강제하지 않는다. 테마 5개와 자유 꾸미기를 각각 확인한다.

최종 보고에는 수정 파일, 실제 실행한 검사, 수정 전후 이미지, 남은 아트 불일치를 명시한다. 파일 검사 성공과 시각 품질 합격을 구분한다.
