## 2. 확인된 문제와 근거

### 2.1 캔버스가 같아도 신체 좌표가 다르다 — P0

`game.js`는 모든 캐릭터를 `360 × 480` 좌표에 렌더링한다. 사용자 PNG는 `1086 × 1448`이다. 그러나 실제 신체는 통일되어 있지 않다.

- `girl01`만 `assets/custom/characters/girl01.png`를 사용한다.
- 나머지는 `game.js`의 다른 비율을 가진 SVG 몸을 사용한다.
- SVG 사람 얼굴은 중심 `(180, 137)`, 반경 `(79, 91)`이어서 턱이 대략 `y=228`에 있다. 세연이 PNG의 턱은 논리 좌표로 대략 `y=157` 부근이다.
- 상의·하의 기본 SVG도 `girl01` 여부에 따라 목둘레와 허리 좌표를 별도로 사용한다. 예를 들어 허리 기준이 약 `250`과 `305~307`로 갈린다.

따라서 CSS에서 전체 크기를 맞추거나 개별 모자에 `scale()`을 추가해도 목·어깨·허리·신발이 함께 맞아지지 않는다. **동일한 신체 도형과 기준점에서 네 캐릭터를 다시 구성해야 한다.**

### 2.2 몸에 기본 옷과 발이 합쳐져 있다 — P0

- 세연이 PNG에는 흰 티셔츠, 분홍 반바지, 맨발이 들어 있다.
- 기본 SVG 몸에도 티셔츠·반바지·신발처럼 보이는 발 도형이 들어 있다.
- 새 상의·원피스·신발을 위에 올려도 아래에 그려진 기존 소매, 어깨선, 발끝이 남을 수 있다.

**전체 몸 위에 옷을 추가하는 방식만으로는 해결할 수 없다.** 기본 옷을 별도 레이어로 분리하고, 새 파츠가 맡는 신체 부위는 기존 몸에서 그리지 않거나 정확히 잘라야 한다.

### 2.4 그림체와 아이템 이름이 일치하지 않는다 — P1

- 사용자 PNG 헤어·원피스는 부드러운 음영을 가진 일러스트다.
- 기본 헤어·모자·여러 의상은 단순 SVG 경로와 단색 채우기를 사용한다.
- 모자 장식에 반복되는 문자/이모지와 일부 헤어의 비슷한 외곽은 실제 상품 그림처럼 보이지 않는다.
- 같은 도형에 색만 바꾼 파츠는 포니테일·토끼 신발 등 이름이 의미하는 형태를 충분히 보여주지 못한다.

## 3. 원인 해결을 위한 최소 구조

다음 네 요소만 정리한다.

1. **공통 신체 규격 하나**: 같은 포즈·실루엣·부위 좌표.
2. **캐릭터별 얼굴과 색상**: 공통 몸 위의 정체성 파츠.
3. **아이템별 그림과 신체 영역 정보**: 옷 그림, 피부/털색 연결 부위, 가릴 기존 부위.
4. **기존 공통 렌더러의 합성 순서**: 모든 화면에서 같은 결과를 사용.

공통 좌표/팔레트/몸 도형은 작은 `assets/characterRig.js` 하나에 모은다. 아이템별 파츠 정보는 기존 `assets/assetRegistry.js`를 확장한다. `data.js`는 기존 카테고리·ID·이름·태그를 유지한다. 별도 범용 에셋 엔진을 만들지 않는다.

### 3.1 공통 규격

| 항목 | 규격 |
|---|---|
| 규격 ID | `preschool-v1` — V7에서 승인할 최초 공통 신체 |
| 원본 캔버스 | `1086 × 1448`, 투명 PNG |
| 논리 캔버스 | `360 × 480` |
| 좌표 환산 | 원본 좌표 × `360 / 1086` = 논리 좌표. 세로도 같은 비율 |
| 포즈 | 정면, 팔은 몸 옆에서 약간 벌림, 발은 동일한 간격과 방향 |
| 몸 비율 기준 | 현재 세연이의 부드러운 일러스트 비율을 출발점으로 사용 |
| 화면 확대/축소 | 완성된 캐릭터 전체 그룹에 한 번 적용 |
| 착용 파츠 위치 | 승인한 공통 좌표에 고정. 캐릭터별 임의 이동 금지 |

머리/몸 PNG를 각자 `object-fit: contain`으로 맞추거나 알파 영역을 자동 중앙 정렬하지 않는다. 투명 여백도 좌표 계약의 일부다.

### 3.2 기준점 확정 절차

아래 숫자는 **설계 착수용 목표값**이다. 정밀 측정이 끝난 확정 좌표로 오해하지 않는다. 첫 단계에서 기존 세연이 원본 위에 기준선을 표시하고 승인 가능한 공통 실루엣을 만든 뒤 실제 값을 저장한다.

| 기준점 | 논리 좌표 초안 | 목적 |
|---|---|---|
| 중심선 | `x=180` | 머리·몸·허리 공통 중심 |
| 머리 피부 최상단 | `y≈24` | 두피 덮개 범위 |
| 턱 끝 | `(180, ≈157)` | 얼굴/목 연결 |
| 목둘레 중심 | `(180, ≈168)` | 상의·원피스 목둘레 |
| 어깨 높이 | `y≈181` | 소매/민소매 연결 |
| 좌우 어깨 | `x≈119 / 241` | 실제 몸 곡선에서 재측정 |
| 허리 중심 | `(180, ≈250)` | 상의 하단·치마·바지·원피스 |
| 손/손목 영역 | `y≈290~305` | 소매와 소품 기준, 실제 관절 재측정 |
| 좌우 발목 중심 | `x≈151 / 209`, `y≈430` | 신발 입구/바짓단 연결 |
| 기본 신발 바닥 | `y≈466` | 동일한 지면 접촉 |

어깨 폭·손목·발목·골반은 PNG의 가로 알파 범위만으로 측정하지 않는다. 같은 행에 팔·손·옷이 섞여 있기 때문이다. 해부학적 연결점과 의상 경계선을 직접 표시한다.

승인할 기준선: 머리 상단/좌우/턱, 눈 보호 영역, 목둘레, 좌우 어깨 곡선, 팔꿈치/손목, 허리 곡선, 골반/다리 중심, 발목 입구와 바닥. 좌우를 단순 대칭 복제하기 전에 원본 포즈가 대칭인지 확인한다.

### 3.3 확인한 원본 경계 — 좌표 참고용

아래는 원본 PNG에서 알파 값 32 이상인 픽셀의 bounding box다. 오른쪽/아래 좌표는 제외 경계다. **형태가 다르므로 bounding box를 같게 만드는 것은 착용 수정 기준이 아니다.**

| 파일 | 원본 알파 경계 `(left, top, right, bottom)` |
|---|---|
| `characters/girl01.png` | `(229, 73, 856, 1407)` |
| `clothes/hair_01.png` | `(290, 40, 795, 470)` |

| `clothes/hair_05_v1.png` | `(269, 44, 836, 508)` |
| `clothes/top_01.png`, `top_03.png` | `(343, 500, 743, 770)` |
| `clothes/pants_02.png` | `(386, 721, 736, 1338)` |
| `clothes/dress_05_v3.png` | `(168, 468, 919, 1215)` |
| `clothes/shoes_01.png` | `(390, 1250, 696, 1404)` |

예를 들어 신발 바닥이 서로 다르다는 사실만으로 오류라고 단정할 수 없다. 굽·밑창 두께는 다를 수 있다. 발목 연결, 발의 방향, 지면 접촉, 원래 발이 새는지를 함께 검사해야 한다.

## 4. 기본 몸 재구성

### 4.1 몸의 분리 단위

기존의 옷이 그려진 통짜 몸 이미지를 착용용 바디로 계속 사용하지 않는다. 다음 부위를 정적 그룹으로 분리한다.

- 머리 피부/털 외곽과 얼굴 표정.
- 뒤/앞 귀. 동물 귀도 같은 머리 좌표에 부착.
- 목·몸통.
- 좌우 팔과 손. 소매에 가려지는 부분과 보이는 부분을 구분.
- 골반·좌우 다리.
- 좌우 맨발. 신발 선택 시 해당 부위 교체/숨김 가능.

복잡한 관절 애니메이션은 필요 없다. PNG 얼굴/귀와 부드러운 색상·음영을 가진 SVG 몸 파츠를 혼합해도 된다. 모든 피부/털 영역은 같은 팔레트를 써야 하며, 평평한 도형 몸을 완성 일러스트로 간주하지 않는다.

### 4.2 기본 옷은 별도 파츠

- 기본 티셔츠와 반바지는 몸에서 제거하고 별도 기본 놀이복 파츠로 둔다.
- 원피스를 선택하면 기본 상의·하의도 렌더링하지 않는다.
- 상의+하의를 선택하면 그 자리에 기본 옷이 남지 않는다.
- 상의나 하의 선택을 해제하면 해당 부위에 기본 놀이복이 돌아온다. 기본 놀이복을 새 옷 위에 그리지 않는다.
- 몸 파츠 제작용 도형이 필요해도 어린이 게임에 속옷 차림의 완성 화면을 노출하지 않는다. 제작 reference는 옷을 입은 캐릭터나 개별 부위로 준비한다.
- 신발은 기본 편한 신발을 두고 교체 선택한다. 선택된 신발을 다시 눌러 맨발로 바꾸는 동작은 이 보완 범위에서 없앤다. 초기화와 빈/오래된 저장 상태도 기본 신발을 렌더링한다.

신발의 기본값 정책 변경은 `outfit-rules.js`와 관련 문서에 명시한다. “신발이 선택됐는데 맨발처럼 보이는 오류”와 “명시적인 맨발 모드”를 혼동하지 않는다. 이번 아이용 UI에는 맨발 모드를 새로 추가하지 않는다.

### 4.3 네 캐릭터의 통일

| 캐릭터 | 통일할 요소 | 유지할 요소 |
|---|---|---|
| 세연이 | 공통 몸·머리 실루엣·포즈 | 기존 얼굴의 귀여운 인상 |
| 하늘이 | 동일 | 다른 얼굴 특징과 피부 톤 |
| 곰돌이 | 동일 | 둥근 귀·주둥이·갈색 털 |
| 토끼 | 동일 | 긴 귀·작은 코·밝은 털 |

동물 귀는 머리 위 안전 영역 안에 배치한다. 토끼만 귀 때문에 전체 몸을 축소하지 않는다. 공통 머리보다 큰 동물 얼굴을 따로 확대해 옷 목둘레와 부딪히게 하지 않는다. 털/주둥이 표현은 같은 얼굴 외곽 내부 또는 승인한 귀 영역 안에서 해결한다.

## 5. 의상 자체의 피부·털색 구간

### 5.1 사용자 요구를 적용하는 방식

**의상은 옷 그림 한 장과 필요한 신체 연결 영역 정보를 함께 갖는다.** 피부색을 분홍 PNG에 고정해서 네 캐릭터에 공통 사용하지 않는다. 옷 그림은 그대로 쓰고, 그 옷의 피부/털 구간만 현재 캐릭터 팔레트로 그린다.

기본 팔레트 토큰:

- `skinBase`: 피부 또는 털 기본색.
- `skinShadow`, `skinHighlight`: 같은 부위의 그림자/밝은 면.
- `outline`: 따뜻한 갈색 윤곽선. 밝은 털도 검은 굵은 테두리로 바꾸지 않는다.
- 필요할 때만 `innerEar`, `blush`, `hairBase` 등 실제 사용 토큰 추가.

`data.js`에 있는 기존 `skin` 색은 출발값이다. 세연이 PNG의 실제 피부 음영과 정확히 같다고 가정하지 않는다. 얼굴·목·어깨·손·발목을 합성한 화면에서 색을 확인하고 일치하는 팔레트를 정한다. 흰 토끼/갈색 곰에게 사람 살색을 덮지 않는다.

### 5.2 의상별 영역과 몸 숨김

| 파츠 | 의상에 포함할 색상 구간 | 숨기거나 잘라야 할 기존 몸/옷 |
|---|---|---|
| 반팔 상의 | 목둘레 안쪽, 소매 끝의 팔 연결 | 기본 티셔츠, 기존 소매 윤곽, 중복 어깨선 |
| 민소매 상의/원피스 | 좌우 어깨와 겨드랑이 접점, 목둘레 안쪽 | 기존 어깨선/소매, 가려지는 몸통 |
| 퍼프 소매 원피스 | 목둘레, 소매 끝 연결 | 기본 옷 전체, 소매 아래 중복 선 |
| 치마/바지 | 허리 연결이 노출될 때만 작은 허리 영역 | 기본 반바지, 새 하의 안쪽 중복 골반선 |
| 닫힌 운동화/구두/장화 | 필요한 발목 구간. 발가락은 신발 내부에서 숨김 | 기본 발 전체 또는 신발 아래 해당 구간 |
| 샌들 | 밑창 위 발 피부/털, 끈 사이 발등, 발목 | 기존 발 도형. 샌들 전용 발이 대신 표시 |
| 모자 | 필요한 경우 귀 연결부. 두피 누출은 헤어색 덮개로 해결 | 모자 안쪽으로 들어가는 머리카락/귀 부분 |

민소매에서 보이는 어깨 피부 자체는 정상이다. 제거할 것은 이중 선, 빈 공간, 옷 밖으로 튀어나온 기본 소매다. 모자를 썼다고 얼굴을 살색 도형으로 덮는 방식은 사용하지 않는다.

### 5.3 영역 소유권

각 신체 영역은 한 번만 그린다.

1. 선택된 파츠의 `hidesBodyRegions`를 모은다.
2. 그 영역은 기본 몸에서 제외하거나 해당 마스크로 자른다.
3. 파츠의 `skinRegions`를 캐릭터 팔레트로 그린다.
4. 그 위에 옷 그림과 필요한 끝단/끈을 그린다.

두 파츠가 같은 영역을 요구하면 정상적인 조합인지 확인한다. 신발과 바지의 발목 겹침처럼 허용된 경우만 정해진 순서를 적용한다. 그 외 충돌은 데이터 오류로 보고하고 무작위 선택까지 차단한다.

연결 부위는 옷 안쪽으로 논리 좌표 약 `2~4px` 겹치게 제작하되, 실제 확대 화면에서 틈이 사라지는 최소값을 확정한다. 겹침은 **천 아래**에 있어야 한다. 살색 패치를 천 위에 올려 소매·장식을 지우면 안 된다.

### 5.4 최소 데이터 예시

다음은 구현 예시이며 현재 존재하는 스키마가 아니다. 이름·파일 경로는 구현 단계에서 실제 원본에 맞춘다. 기존 문자열 registry 항목은 읽을 수 있게 유지한다.

```js
// assets/assetRegistry.js — 아이템 ID는 유지한다.
top_01: {
  rigId: 'preschool-v1',
  status: 'ready',
  asset: 'assets/custom/clothes/top_01.png',
  skinRegions: ['top01Neck', 'top01LeftCuff', 'top01RightCuff'],
  hidesBodyRegions: ['baseTop', 'leftShoulderEdge', 'rightShoulderEdge']
},
shoes_04: {
  rigId: 'preschool-v1',
  status: 'ready',
  asset: 'assets/custom/clothes/shoes_04.png',
  footwearType: 'sandal',
  skinRegions: ['sandalLeftFoot', 'sandalRightFoot'],
  hidesBodyRegions: ['leftFoot', 'rightFoot']
},
hair_04: {
  rigId: 'preschool-v1',
  status: 'ready',
  back: 'assets/custom/clothes/hair_04_back.png',
  front: 'assets/custom/clothes/hair_04_front.png',
  scalpProfile: 'ponytail',
  hatProfile: 'ponytail'
}
```

- `skinRegions`는 `assets/characterRig.js`의 로컬 도형/마스크를 참조한다. 같은 도형을 아이템마다 복사하지 않는다.
- 목둘레가 실제로 다른 옷에는 해당 옷의 도형이 필요하다. 모든 상의에 같은 원형 살색 패치를 얹지 않는다.
- 그림의 목둘레/팔입구와 색상 구간이 서로 맞는 한 묶음으로 제작·검수한다.
- 피부/털을 덮는 PNG는 여러 색을 추가 생성하기보다 팔레트 SVG를 사용한다. PNG 얼굴은 얼굴 아래 목과 닿는 색까지 맞춘다.
- `status`는 제작 중 노출 방지에 사용한다. 기존 완료 자산을 일괄 숨기거나 임의로 `ready`로 찍어 완료 처리하지 않는다.
- 객체 항목의 런타임 경로 변환은 기존 `runtimeAsset()`을 재사용한다. 문자열/객체를 읽는 작은 함수 하나로 통일한다.
- HTML 파일의 스크립트 로딩 순서, 감사 스크립트의 registry 순회 방식도 함께 수정한다. 현재 정규식 기반 PNG 탐색이 새 경로를 빠뜨리지 않는지 확인한다.

## 6. 헤어·모자 보완

### 6.1 헤어는 세 부분으로 합성

1. `hairBack`: 얼굴·몸·옷 뒤의 머리카락. 포니테일/양갈래 뒷부분.
2. `hairCap`: 공통 머리의 노출되면 안 되는 두피를 덮는 헤어색 영역.
3. `hairFront`: 앞머리·얼굴 옆 가닥. 얼굴 보호 영역을 침범하지 않음.

현재 사용자 헤어 PNG는 `part === 'back'`일 때 아무것도 그리지 않아 전체 그림이 한 번에 앞쪽에 놓인다. 새 헤어는 필요한 경우 앞/뒤를 분리한다. 단발처럼 분리가 필요 없는 부분까지 파일을 늘릴 필요는 없다.

`hairCap`은 얼굴과 두피를 구분한 승인 마스크 안에서만 그린다. 얼굴 전체를 갈색 타원으로 덮거나, 이마를 모두 앞머리로 내려서 대머리를 감추지 않는다. 털 캐릭터도 머리카락 밖에 피부/털 머리 경계가 이상하게 남지 않도록 같은 규격을 적용한다.

### 6.2 눈 보호 영역

- 두 눈·눈썹·표정의 핵심 부위를 보호 영역으로 지정한다.
- 앞머리는 승인한 이마 경계 아래로 내려오지 않는다. 의도적인 한쪽 눈 가림 헤어는 이번 3세용 목록에서 만들지 않는다.
- 모자 챙은 눈 위의 정해진 선에서 끝난다. 눈을 가리는 모자는 위치만 조정할 것이 아니라 챙 형태도 다시 제작한다.
- 피부가 보여야 하는 이마와 감춰야 하는 두피를 검사 마스크에서 구분한다.

### 6.3 헤어 우선 처리

- `hair_04`: 이미 확인한 두피 노출을 우선 수정. 포니테일의 뒷부분 위치와 모자 조합도 확인.
- `hair_06~08`: 단색 도형을 사용하지 않고 이름에 맞는 실제 헤어 실루엣으로 재제작.
- `hair_01~05`: 기존 그림체는 참고하되 공통 머리와 맞는지 다시 확인. 예쁜 PNG라는 이유로 면제하지 않는다.
- 곰/토끼 기본 머리에는 사람 머리 꼬리처럼 남는 기본 SVG를 재사용하지 않는다. 공통 머리에 맞는 짧고 귀여운 앞머리 또는 종별 기본 털 스타일을 준비한다.

### 6.4 모자는 형태별 착용 경계로 맞춘다

기존 `cap/sunhat/beanie/crown` 분류는 유지 가능하나, 한 개의 `translate/scale` 값으로 모든 모자를 맞추지 않는다.

각 형태에 필요한 기준:

- 머리에 닿는 안쪽 곡선, 중심, 꼭대기, 챙 하단.
- 모자 안에 들어가 가려지는 상단 머리카락 마스크.
- 얼굴 앞에 와야 하는 챙과 뒤로 가야 하는 부분의 구분.
- 곰/토끼 귀를 보여줄지 접어 숨길지의 명시적 규칙.

공통 신체를 유지하고 헤어 스타일별로 필요한 소수의 착용 프로필만 둔다. 4캐릭터 × 8헤어 × 10모자마다 임의 보정값을 만들지 않는다. 큰 포니테일은 모자용 뒤머리 변형을 준비하거나 헤어 마스크로 수납한다. 안전하게 수납할 수 없는 조합을 조용히 깨뜨리지 않는다.

모자 10개는 기존 단순 SVG/문자 장식 대신 새 일러스트로 제작한다. 꽃·별·리본 등 장식도 같은 선·음영으로 그린다. 이모지 폰트 모양에 의존하지 않는다.

## 7. 신발과 하의 연결

### 7.1 닫힌 신발

- 좌우 발목 중심을 고정하고, 발등 방향·발 간격을 공통 몸에 맞춘다.
- 기본 발끝/발톱/기존 신발은 새 신발 밖으로 보이지 않게 숨긴다.
- 발목은 신발 입구 안으로 들어간다. 발목과 입구 사이에 배경색 틈이 있으면 실패다.
- 밑창은 같은 지면 기준에 닿는다. 좌우 높이가 의도 없이 달라지거나 신발이 떠 있으면 실패다.
- 장화는 발목/종아리의 가리는 범위가 넓다. 구두와 같은 마스크를 적용하지 않는다.

### 7.2 샌들

샌들의 밑창 위에 **샌들 자체의 발 피부/털 영역**을 그린다. 그 위에 발등 끈을 배치한다. 기존 맨발 PNG를 그대로 둔 채 샌들 테두리만 추가하지 않는다.

피부색 발이 신발 끈 바깥으로 삐져나오면 실패다. 곰/토끼에게는 같은 위치에 현재 털색이 들어가야 한다. 발 형태는 공통 규격을 유지한다.

### 7.3 바짓단·신발 우선순위

기본은 하의 → 발목 연결 → 신발이다. 장화가 바짓단을 덮어야 하는 경우처럼 실제 필요한 프로필만 사용한다. 바지 전체를 신발 위로 올려 밑창까지 가리지 않는다. 바짓단이 신발 바깥으로 내려오는 디자인은 끝단 파츠만 마지막에 그린다.

신발 이미지 전체 크기를 키워 발을 억지로 덮는 수정은 금지한다. 발목은 맞아도 밑창/폭이 과장되면 균형이 틀어진다.

## 8. 중앙 합성 순서

`data.layers`와 `avatarSvg()`를 기준으로 순서를 한 곳에서 관리한다. 아이템의 카테고리 하나만으로 모든 조각의 앞뒤를 결정하지 않는다.

| 순서 | 그리는 요소 | 규칙 |
|---|---|---|
| 1 | 배경 | 기존 처리 유지 |
| 2 | 뒤 모자·뒤 귀·뒤 머리 | 프로필에 따른 순서, 몸/얼굴 뒤 |
| 3 | 몸·팔다리·목·기본 놀이복 | 소유권에 따라 숨김, 기본 옷은 선택 의상에 의해 교체 |
| 4 | 의상용 피부/털 연결 구간 | 천 아래, 같은 몸 윤곽 중복 금지 |
| 5 | 하의·상의 또는 원피스 | 기존 배타적 선택 규칙 유지 |
| 6 | 신발용 발목/발 → 신발 | 기존 발 숨김, 샌들 끈은 발보다 앞 |
| 7 | 얼굴/머리 앞쪽·필요한 앞 귀 | 목 연결은 천과 자연스럽게 연결 |
| 8 | 두피 덮개·앞머리 | 얼굴 보호 마스크 적용 |
| 9 | 앞 모자·머리장식 | 눈을 가리지 않음 |
| 10 | 목걸이·안경·가방·소품 | 목걸이 등은 필요 부위 순서만 조정, 얼굴 훼손 금지 |
| 11 | 앞손 또는 소품 손잡이 부분·효과 | 실제 소품 파지 필요 시만 추가 분리 |

표의 숫자는 구현용 z-index 확정값이 아니다. 실제 조각별 앞뒤 순서를 정한 뒤 기존 레이어 상수로 표현한다. 머리 전체 이미지를 마지막에 그려 목걸이와 소매를 덮지 않도록 분리한다.

편집 화면, 캐릭터 선택/홈 미리보기, 완성 화면, 사진첩, 저장 사진은 같은 합성 함수를 사용한다. `photoSvg()`의 외곽 이동/확대만 유지하고 착용 좌표를 따로 보정하지 않는다. 이미지 단독 썸네일도 승인한 파츠 경계를 기준으로 표시한다.

## 9. 그림체 재제작 기준

### 9.1 목표 그림체

- 기존 세연이 얼굴과 부드러운 원피스 PNG를 스타일 기준으로 사용한다.
- 한국 어린이 애니메이션에 어울리는 오리지널 캐릭터. 특정 작품의 인물을 닮게 만들지 않는다.
- 따뜻한 갈색 윤곽, 둥근 형태, 파스텔 천 색, 2~3단계의 부드러운 음영.
- 빛 방향·그림자 농도·광택 표현을 통일한다.
- 옷은 목둘레·소매·봉제선·밑단 구조가 읽히게 만든다. 작은 화면에서 과도한 장식은 줄인다.
- 피부/털 연결 도형은 정밀한 마스크용 보조 자산으로 사용한다. 완성 옷·모자·헤어를 단색 도형만으로 대체하지 않는다.

### 9.2 현재 아이템 현황

V6 코드 기준 총 104개다. 원래 초기 목표인 약 90개를 이유로 임의 삭제하지 않는다.

| 카테고리 | 총수 | 사용자 PNG | 기본 SVG 등 |
|---|---:|---:|---:|
| 헤어 | 8 | 5 | 3 |
| 모자 | 10 | 0 | 10 |
| 상의 | 12 | 3 | 9 |
| 원피스 | 12 | 12 | 0 |
| 치마 | 8 | 3 | 5 |
| 바지 | 8 | 1 | 7 |
| 신발 | 10 | 4 | 6 |
| 머리장식 | 10 | 3 | 7 |

69개는 기본 렌더링으로 남은 수다. 모두 동일한 정도로 잘못되었다는 뜻은 아니지만, 노출할 품질을 확인하고 거친 그림체는 교체해야 한다. 35개 PNG도 새 규격 적합성을 검수한다.

### 9.3 교체 순서

1. 공통 4캐릭터와 대표 옷/신발 조합.
2. 헤어 8개, 모자 10개, 신발 10개.
3. 상의·원피스·치마·바지 전 항목의 연결 부위.
4. 머리장식·가방·액세서리·소품 중 거친 파츠.

첫 대표 조합이 맞기 전에 모든 의상을 생성하지 않는다. 생성한 파츠가 기준 몸과 다른 비율이면 다음 이미지 생성으로 넘어가지 말고 그 파츠를 교정한다.

제작 중 미완성 파츠는 아이용 화면·마법 코디·이야기 추천에 노출하지 않는다. 숨긴 목록과 개수를 보고한다. 몇 개만 남겨놓고 “모든 아이템 완료”라고 보고하지 않는다. 최종 완료에는 현재 카탈로그 전체의 노출 품질 검수가 필요하다.

## 10. GPT 이미지 제작 지시 템플릿

이미지 생성만으로 정확한 좌표를 보장할 수 없다. 원본의 투명 여백, 포즈, 기준점은 생성 후 측정하고 필요한 재편집을 한다. 참조용 몸/가이드는 최종 착용 PNG에 합쳐 넣지 않는다.

### 10.1 공통 캐릭터 reference

첨부: 기존 세연이 캐릭터, 기존 완성 코디의 스타일 reference, 승인할 공통 기준선 이미지.

```text

첨부한 세연이의 따뜻한 애니메이션 그림체와 공통 기준선을 사용하세요.
네 캐릭터 모두 정면으로 서며 머리/몸의 실루엣, 목, 어깨, 허리,

기존 얼굴 정체성, 사람의 피부색 또는 곰/토끼의 털색과 귀는 유지하세요.
귀 때문에 몸 전체를 축소하거나 얼굴을 크게 늘리지 마세요.

최종 파츠는 얼굴/귀와 몸 부위로 분리해 사용할 예정입니다.
reference의 옷을 착용용 몸 파츠에 합쳐 넣지 않도록 제작 자료를 구분하세요.
```

### 10.2 헤어 재제작/수정

첨부: 승인한 공통 머리, 기존 헤어 PNG, 스타일 reference. 특정 수정에서는 `hair_04`의 두피 누출 확대 캡처도 첨부한다.

### 10.3 모자

```text

큰 모자로 얼굴과 두피 문제를 덮지 마세요.
스타일 reference와 같은 따뜻한 윤곽, 파스텔, 부드러운 음영을 사용하세요.
별/꽃/리본 장식도 직접 그린 일러스트로 표현하고 이모지나 문자를 넣지 마세요.
곰/토끼 귀의 노출 또는 모자 속 수납은 지정한 reference와 일치시킵니다.
최종 파츠는 모자만 투명 배경에 남기고 머리/얼굴/몸/가이드선을 제외하세요.
```

### 10.4 옷과 신발

```text
첨부한 공통 캐릭터의 기준점에 정확히 맞는 [의상/신발 이름]을 제작하세요.
캐릭터 포즈와 신체 크기는 바꾸지 마세요.
목둘레, 어깨, 소매 끝, 허리 또는 좌우 발목과 신발 바닥을 기준선에 맞추세요.
옷과 신발 자체는 기존 세연이 의상과 같은 부드러운 애니메이션 그림체로 제작합니다.
피부/털색은 런타임 보조 파츠로 채울 예정이므로 천 내부의 해당 입구는 투명하게 두세요.
신발은 왼쪽/오른쪽 방향과 발 간격을 유지하세요.
샌들은 발등 피부 영역과 끈이 겹치는 구조를 명확히 나눠 사용할 수 있게 하세요.
최종 의상 파일에는 얼굴, 몸, 다른 옷, 다른 신발, 배경, 문자, 가이드선을 넣지 마세요.
투명 배경과 전체 기준 캔버스의 위치를 유지하세요.
```

생성 도구가 지정 크기를 정확히 출력하지 않으면 균등 비율로 목표 캔버스에 배치한다. 어깨/발목 기준점을 맞추며 크기를 교정하고, 가로·세로를 따로 늘려 그림을 찌그러뜨리지 않는다. 최종 원본은 기존 규격 `1086 × 1448`로 저장한다. 피부/털 마스크는 승인한 옷 입구에 맞춰 코드/벡터로 작성한다.

## 11. 기존 기능과 데이터 보존

### 11.1 호환성

현재 `data.js`는 PNG가 있으면 자동으로 `compatibleCharacters: ['girl01']`을 지정한다. 새 공통 규격을 승인한 파츠는 네 캐릭터 모두에 사용할 수 있도록 실제 `rigId`와 검수 결과를 기준으로 호환성을 결정한다.

- 기존 PNG가 공통 캔버스라는 이유만으로 네 캐릭터 제한을 제거하지 않는다.
- 공통 규격으로 교체하지 않은 파츠는 기존 제한을 유지한다.
- 목록 표시, 선택, 마법 코디, 이야기 추천, 초기화, 사진첩 재렌더링이 같은 판단을 사용한다.
- 상의+원피스, 치마+바지 등 기존 배타 규칙을 보존한다. 색상 연결 파츠는 별도 옷 선택으로 취급하지 않는다.

### 11.2 사진첩

- 기존 `localStorage` 데이터를 삭제하거나 전체 덮어쓰지 않는다.
- 아이템 ID를 유지하므로 새 아트로 같은 코디를 재현할 수 있게 한다.
- 이전 버전의 선택 상태에 없는 신발/기본 옷은 안전한 기본 파츠로 렌더링한다. 저장 데이터는 필요 없이 수정하지 않는다.
- ID가 사라졌거나 미완성인 경우 허용된 기본 파츠로 표시하고, 같은 기록을 유지한다.
- 사진이 이미지로 저장되는지 선택 상태로 저장되는지 기존 경로를 확인한 후 처리한다. 이미 저장된 이미지 파일이 자동으로 새 그림으로 바뀐다고 약속하지 않는다.
- 캐릭터를 바꿨을 때 이전 캐릭터의 피부색이 남지 않게 팔레트를 매 렌더링의 캐릭터 ID에서 가져온다.

### 11.3 화면·스크롤

- `characterPortrait()`의 비세연이 이모지 미리보기를 공통 캐릭터 렌더링으로 바꾼다.
- 카테고리/아이템 가로 스크롤, 선택 강조, 큰 터치 영역을 유지한다.
- 썸네일은 각 파츠의 승인 경계로 만들어 장식·목둘레·신발 바닥이 잘리지 않게 한다.
- 높이가 작은 화면에서도 의상 목록과 완성 버튼에 접근할 수 있어야 한다. 캐릭터 영역을 무조건 고정 높이로 늘리지 않는다.
- 이미지 교체는 로컬 파일의 decode가 끝난 뒤 함께 반영한다. 새 머리가 로딩되는 동안 잠시 대머리가 되거나 한쪽 신발만 바뀌지 않게 한다.
- 로딩 실패 시 현재 정상 코디를 유지하거나 승인한 기본 파츠를 사용한다. 실패한 거친 SVG를 자동 노출하지 않는다.

## 13. 검증 설계

### 13.1 구조 검사 — 기존 도구 확장

- `node --check`, `check-data.js`, `audit-assets.js`를 유지한다.
- `scripts/test-character-compatibility.js`에서 기존 제한과 새 공통 규격의 호환성을 함께 확인한다.
- `scripts/browser-smoke.mjs`의 기존 조작 검증을 유지하고 대표 결함 조합과 색상 영역을 추가한다.
- `scripts/convert-assets.py`, `scripts/verify-runtime-assets.py`로 PNG↔WebP 결과를 확인한다.
- 동일 캔버스 검사 이름/보고는 “원본 캔버스 규격 검사”로 표현한다. 해당 PASS를 착용 품질 PASS로 표시하지 않는다.
- 새 피부/털 도형의 ID 누락, 알 수 없는 palette token, 잘못된 rigId, 불허한 영역 중복을 검출한다.
- 현재 선택 규칙을 여러 화면에서 중복 구현하지 않는다. 공통 함수 한 곳을 검증한다.

### 13.2 실제 픽셀과 확대 이미지 검사

전체 화면과 함께 다음 확대 crop을 저장한다.

1. 머리 꼭대기/양쪽 두피와 앞머리.
2. 목둘레/좌우 어깨/소매 끝.
3. 허리와 하의 겹침.
4. 좌우 발목/발등/신발 바닥.

자동 검사는 **예상 영역 마스크** 안에서만 한다. 얼굴이 살색이라는 이유로 “두피 노출”로 분류하거나, 배경색과 피부색이 비슷한 화면에서 RGB 한 값만 검사하지 않는다.

| 항목 | 판정 방법 |
|---|---|
| 동일 신체 | 공통 기준점 데이터 일치 + 네 캐릭터 오버레이. 핵심 윤곽은 승인 후 논리 좌표 1px 이내, 귀/머리카락은 제외 |
| 두피 누출 | 얼굴/허용 이마를 제외한 두피 영역이 헤어/모자에 덮이는지 alpha/합성 마스크 확인 + crop 검수 |
| 얼굴 보호 | 앞머리/모자 불투명 영역이 눈 보호 영역에 침범하지 않는지 확인 |
| 어깨/소매 연결 | 천 안쪽 겹침 확보, 배경 틈 없음, 이중 몸 선 없음. 각 옷의 연결 마스크로 검사 |
| 색상 일치 | 같은 캐릭터의 인접 피부/털 기본색과 음영 연속성. 픽셀/팔레트 검사와 시각 검수 병행 |
| 닫힌 신발 | 가려야 할 기본 발 영역의 렌더링 없음, 발목 입구 연결, 밑창 접촉 |
| 샌들 | 전용 발 도형이 밑창/끈 안에 위치, 다른 캐릭터 피부색 없음 |
| 균형 | 과한 머리·모자 폭, 너무 큰 신발, 몸 축소 여부를 비교 이미지로 확인 |

안티앨리어싱 오차와 실제 틈을 구분한다. 기계 검사 임계값은 승인된 대표 이미지에서 정한다. 1px 허용을 근거로 길게 드러난 피부 윤곽을 통과시키지 않는다. 선명한 두피 조각, 이중 어깨선, 떨어진 신발은 크기와 관계없이 시각 검사 실패다.

### 13.3 조합 검증표

| 대상 | 전수/대표 기준 |
|---|---|
| 헤어만 | 4캐릭터 × 8헤어 = 32 조합 |
| 헤어+모자 | 4 × 8 × 10 = 320 조합. 기준 viewport에서 전수 합성/검사 |
| 원피스 | 4 × 12 = 48 조합 |
| 신발 | 4 × 10 = 40 조합. 닫힌/샌들/장화 대표를 바지와도 조합 |
| 상의/하의 | 모든 상의·치마·바지를 네 캐릭터에 적어도 한 번 적용. 목/어깨/허리 형태가 다른 조합 추가 |
| 색상 전환 | 같은 옷을 입은 상태에서 세연이→하늘이→곰→토끼. 이전 palette 잔류 검사 |
| 동작 | 선택, 해제/기본 복귀, 초기화, 되돌리기, 마법 코디, 이야기 추천, 캐릭터 변경 |
| 화면 | 홈, 편집, 완성, 사진첩, 저장 이미지 |

전수 머리 조합은 한 viewport에서 자동 비교 이미지를 생성한다. 320장의 큰 캡처를 무조건 사람에게 넘기지 말고 머리 crop을 묶은 비교표와 실패 목록을 만든다. 위험 조합과 대표 전체 코디는 두 번째 viewport에서도 확인한다.

모바일 기준: `390×844`, `412×915`. 작은 높이 `360×640`에서는 스크롤과 버튼 접근성을 추가 확인한다. 데스크톱에서는 기존 가운데 배치·마우스 스크롤을 확인한다. 브라우저 viewport 검증과 실제 Galaxy 기기 확인은 따로 보고한다. 실제 기기를 쓰지 않았다면 기기 확인 완료라고 쓰지 않는다.

## 14. 배포본·캐시 확인

이 문서 작성 단계에서는 배포하지 않는다. 향후 구현 후 배포할 때:

1. `.github/workflows/pages-v5-test.yml`의 선택 ref가 실제 수정 브랜치인지 확인한다. 이름과 단계 설명은 현재 버전을 나타내도록 수정한다.
2. 성공한 배포 run의 `headSha`와 로컬/원격 완료 커밋이 같은지 확인한다.
3. 배포용 `build-info.json` 같은 작은 버전 파일을 Actions에서 생성해 정확한 SHA를 확인할 수 있게 한다. 개발자 정보는 아이의 플레이 화면에 넣지 않는다.
4. `sw.js`의 정적 자산과 캐시 버전을 갱신한다. registry의 새 앞/뒤 헤어와 필요한 모든 로컬 자산을 포함한다.
5. 새 브라우저 세션과 기존 캐시가 있는 세션을 모두 열어 V7 그림이 실제로 뜨는지 확인한다.
6. 공개 URL에서 대표 결함 조합을 다시 캡처하고 버전과 함께 기록한다.

워크플로 성공, 서비스 워커 파일 변경, 사이트 HTTP 200은 각각의 확인 항목이다. 이 사실만으로 아트 싱크나 오래된 캐시 업데이트까지 완료했다고 말하지 않는다.

| 파일 | 변경 목적 |
|---|---|

| `outfit-rules.js` | 공통 규격 호환성, 신발 기본/교체 정책, 선택 규칙 유지 |

| 기존 감사·회귀 검증 스크립트 | 캔버스와 착용 검사 분리, 새 metadata/연결 부위 검증 |

관련 없는 음악·배경·게임 모드·축구 게임 저장소는 수정하지 않는다. 기존 원본을 덮기 전 Git에 보존한다. 중간 생성물은 임시 폴더에 두고 최종 registry에는 승인한 파일만 연결한다.

## 16. 최종 완료 조건

- [ ] 네 캐릭터가 같은 신체/머리 기준점과 포즈를 사용한다.
- [ ] 귀 때문에 캐릭터 몸 크기가 달라지지 않는다.
- [ ] 옷을 바꿔도 기존 티셔츠·반바지·어깨선이 남지 않는다.
- [ ] 모든 헤어에서 의도하지 않은 살색/털색 두피가 새지 않는다.
- [ ] 앞머리와 모자 챙이 눈·표정을 가리지 않는다.
- [ ] 모자와 머리 사이에 틈이나 비정상 관통이 없다.
- [ ] 헤어·모자·전체 노출 의상의 그림체가 기준 일러스트와 어울린다.
- [ ] 옷의 피부/털 영역이 각 캐릭터 색과 맞고 이중 윤곽이 없다.
- [ ] 닫힌 신발 밖에 원래 맨발이 보이지 않는다.
- [ ] 신발 입구와 발목이 연결되고 밑창이 지면에 닿는다.
- [ ] 샌들은 전용 발 색상 영역과 끈/밑창이 자연스럽게 합성된다.
- [ ] 네 캐릭터 모두 승인한 카탈로그 의상을 사용할 수 있다. 미완성/비호환 예외는 명시한다.
- [ ] 가로/세로 스크롤과 큰 버튼 접근성이 유지된다.
- [ ] 홈·완성·사진첩·저장 이미지가 같은 착용 상태를 보여준다.
- [ ] 기존 사진첩 기록을 보존하며 오프라인/캐시 업데이트가 작동한다.
- [ ] 캔버스 규격과 실제 착용 검사를 별도로 통과했다.
- [ ] 배포를 수행했다면 실제 공개본 SHA와 결함 조합 화면까지 확인했다.

한 항목이라도 미완료면 남은 항목을 구체적으로 보고한다. 일부 대표 코디가 예쁘게 보이는 상태를 전체 완료로 표현하지 않는다.
